I utilized the R2D2 framework as the feature detection algorithm. 
From Fig.~\ref{fig:1} and Fig.~\ref{fig:2}, it can be observed that most keypoints are 
concentrated around visually distinctive regions of the image, such as object boundaries, 
textured surfaces, and high-contrast areas. The clustering of keypoints occurs because R2D2 
detects features across multiple scales, which can lead to overlapping detections when strong 
structures are present at several pyramid levels. In the following plots, the radius of 
each circle represents the detected scale of the corresponding keypoint, illustrating the multi-scale 
nature of the detector.

The radius of each green circle represents the scale predicted by R2D2 for that keypoint, corresponding to the 
size of the image region that contributes to its descriptor. Larger circles indicate coarse-scale features 
that remain stable across viewpoint and blur changes, while smaller circles 
correspond to fine-scale texture details. The variation in circle sizes illustrates the multi-scale nature of 
the detector, allowing robust matching across different levels of zoom and scene detail.
Since the R2D2 framework natively provide "scores" for each keypoint, it's easy to identify which keypoints
are less reliable when we perform image matching in the later steps.

\subsubsection{Feature Matching}

The feature matching pipeline used in this assignment is implemented across three scripts in the repository:
	\texttt{tools/R2D2.py}, \texttt{tools/matcher.py}, and \texttt{starter\_code\_feature.py}. The following summarizes the
implementation, parameters, and the filtering rules applied during matching and depth computation.

\paragraph{Overview}
\begin{itemize}
    \item \texttt{tools/R2D2.py} performs feature detection and descriptor extraction using the R2D2 model. It produces
        per-image files containing \texttt{keypoints} (pixel coordinates and scale), \texttt{descriptors} (128-d vectors), and
        \texttt{scores} (reliability values).
    \item \texttt{tools/matcher.py} implements brute-force L2 nearest-neighbour matching with Lowe's ratio test and simple
        geometric constraints (vertical epipolar tolerance and disparity sign).
    \item \texttt{starter\_code\_feature.py} orchestrates extraction and matching, computes disparity and depth using the
        stereo calibration, applies conservative filtering, writes the sparse depth predictions to \texttt{P3\_result.txt}, and
        generates diagnostic visualizations.
\end{itemize}

\paragraph{Feature extraction (\texttt{tools/R2D2.py})}
The R2D2 extractor is invoked (via \texttt{r2d2/extract.py}) to produce a sidecar \texttt{.r2d2} file per image. Each
file stores arrays loaded with NumPy:
$ \text{keypoints}\in\mathbb{R}^{N\times 3},\quad\text{descriptors}\in\mathbb{R}^{N\times 128},\quad\text{scores}\in\mathbb{R}^N.$
Keypoints are in pixel coordinates $(u,v)$ and include a scale value.

\paragraph{Descriptor matching (\texttt{tools/matcher.py})}
Let $L$ denote left descriptors and $R$ denote right descriptors. Matching proceeds as follows:
\begin{enumerate}
    \item Compute the pairwise L2 distance matrix $D\in\mathbb{R}^{|L|\times|R|}$ with entries $D_{ij}=\lVert d^L_i-d^R_j\rVert_2$.
    \item For each left descriptor find the nearest and second-nearest right descriptors ($j_1, j_2$) and associated distances
        $d_0=D_{i,j_1}$ and $d_1=D_{i,j_2}$.
    \item Apply Lowe's ratio test and a distance threshold:
        \[\text{ratio\_mask}_i = (d_0/d_1 < \tau_{\mathrm{ratio}}) \;\wedge\; (d_0 \le \tau_{\mathrm{dist}}).\]
        Default code parameters: $\tau_{\mathrm{ratio}}=0.9$, $\tau_{\mathrm{dist}}=5.0$.
    \item Enforce an epipolar (vertical) constraint: $|v^L_i - v^R_{j_1}| < \epsilon_y$ with $\epsilon_y=2$.
    \item Require positive disparity (filter out negative disparities): $u^R_{j_1} < u^L_i$.
    \item The final mask is the conjunction of the ratio, epipolar and disparity masks; matches and their descriptor distances
        are returned as arrays for downstream processing.
\end{enumerate}

\paragraph{Disparity and depth (\texttt{starter\_code\_feature.py})}
For each accepted match (left index $i$, right index $j$) the pixel coordinates are extracted and disparity is computed as
\[\text{disparity} = u_L - u_R.\]
Depth is then estimated from stereo geometry via
\[ z = \frac{f\cdot B}{\text{disparity}},\]
where $f$ is the focal length and $B$ is the baseline obtained by factorizing the projection matrices
(see \texttt{krt\_from\_p} and \texttt{get\_stereo\_calibration}).

\paragraph{Filtering rules}
To avoid invalid or very noisy depth estimates, the implementation applies conservative filters:
\begin{itemize}
    \item Skip matches with disparity $\le 0.1$ (prevents division by zero and ignores extremely small disparities).
    \item Discard depths $z>80\,$m or $z<0$ (long-range predictions are unreliable for evaluation).
\end{itemize}

\paragraph{Output and visualization}
Filtered sparse depth predictions are written to \texttt{P3\_result.txt} with the format
	\texttt{image\_id u v disparity depth}. Diagnostic visualizations are created using OpenCV's \texttt{cv.drawMatches}
and stacked figures (one row per sample) are produced and saved with tight bounding boxes to minimize whitespace.
